补遗：快进到 2020¶

如前所述，*编译器*接受半可读的高级代码作为输入，并产生机器语言作为输出。

像 Arduino 这样的微处理器足够小、用途也足够单一，因此它们既不想要、 也不需要操作系统。然而，Raspberry Pi 足够复杂、功能足够强大，需要操作系统。

当有操作系统时，代码在执行大多数任务时都需要与操作系统协商。操作系统 就像交通警察、酒店预订代理，还有更多角色。除其他事项外，操作系统还必须：

  • 告诉程序何时暂停、何时恢复，以便其他程序能够运行，

  • 掌握可用磁盘空间的清单并进行合理分配，

  • 监视来自程序的服务请求，并确定应由哪些程序来响应这些请求，

  • 保护程序和数据，

等等。

当代码与硬件之间存在操作系统时，看似简单的键盘输入或屏幕输出就会变得 复杂。因此，为了使生成的机器码保持一定的可读性，下面的 C 程序并不 真正尝试输入或输出，因而也不会添加大量依赖于操作系统的代码。相反，它 模仿了 Altair 8800 操作手册中给出的第一个程序。

void main()
{
  char a =  5;
  char b = 10;

  a = a + b;
}

通过使用 char 而不是 int，取值被限制在 8 位，就像在 Altair 8800 上一样。

如果上面的程序保存为 add.c，就可以对其进行编译，并可以从编译器 生成的可执行目标代码文件产生汇编语言/机器语言清单。

重要细节：要理解所产生的汇编语言和机器码，你需要大致了解编译器所 面向的硬件。通常这是运行编译器的硬件，但并非总是如此。例如， **Arduino IDE**（集成开发环境）运行在非 Arduino 处理器上，但产生的是 Arduino 机器码。

在次要程度上，了解操作系统内核的版本、编译器的版本以及所用汇编语言的 “方言”也很有用。

在下面的例子中，这些细节是：

处理器：

8 × Intel® Core™ i7-2960XM CPU @ 2.70GHz

内存：

31.3 GiB of RAM

操作系统类型：

Linux 64-bit

内核版本：

5.4.0-48-lowlatency

编译器：

GNU C Compiler (gcc) version 9.3.0

在 Bash 提示符下：

$ gcc -g -c add.c
$ objdump -drwC -Mintel add.o

（产生汇编语言/机器语言清单还有其他方法。例如，你可以让 GCC 在初始编译 期间生成它。不过，objdump 方法产生的输出更紧凑、更简洁。）

编译器接受源代码并产生*目标*文件。根据源代码以及编译方式的不同，目标 文件可能是函数和子程序的非可执行库（它们被*链接*到一个或多个主程序）， 也可能是完整的可执行程序。Linux 上的*共享目标库*（.so）和 Windows 上的*动态链接库*（.dll）就是前者的例子。例如，这样的库可能包含 数学算法的高效实现，或特殊的图形函数。

目标文件能够、而且在大多数系统上确实包含的不仅仅是机器语言。它们可以 包含一个“数据”段，其中保存着程序中使用的所有常量，以及有关在内存中 何处放置数据和可执行代码的信息。在 Linux（以及其他类 Unix 系统）上， 目标文件以 Executable and Linkable Format 格式存储，更常见的叫法是 它的缩写 ELF。

objdump 对二进制目标文件进行逆向工程，试图把它从不可打印的乱码 变回人类可读的形式——不过有些信息，比如原始变量名，可能会丢失。

objdump 对被要求做什么没有任何预设概念。命令中的选项 -Mintel 明确声明 objdump 应假定所使用的指令集是 Intel， 因此机器语言应被翻译回 Intel X86 architecture 助记符。

objdump 的输出如下：

add.o:     file format elf64-x86-64


Disassembly of section .text:

   4:        55                      push   rbp

利用维基百科的 X86 architecture 条目，可以将上述内容解释为：

用到的寄存器¶

助记符

名称

rbp

基址指针

rsp

堆栈指针

eax

累加器（仅低 32 位）

edx

数据（仅低 32 位）

al

累加器（仅低 8 位）

  1. endbr64 超出了本文档的范围。好奇的读者可以参考 StackOverflow 上的 问题 What does endbr64 instruction actually do?。就所有实际目的而言， 它在这段代码中就是一条 nop，可以安全地忽略。

  2. 将 *基址指针*（rbp）的当前状态压栈保存。基址指针指向一个通常存放 数据（而非代码）的区域。

  3. 将 堆栈指针*（``rsp``）的值移入基址指针（``rbp``）。我相信这是一种 编译器优化：由于数据量相对较小，且每个数据元素的尺寸很小，编译器 （我**认为*）选择把堆栈用作数据存储区，而不是通常分配给数据的内存 区域。堆栈比数据区域小，但访问速度更快。

  4. 将值 5（0x5）移动到 rbp - 2 指向的存储单元。这就是 C 程序中的 char a = 5;。

  5. 将值 10（0xa）移动到 rbp - 1 指向的位置。这对应于 C 程序中的 char b = 10;。

  6. 将 a 移入 累加器*（``eax``）的低 32 位，将 ``b`` 移入 *数据寄存器 （edx）的低 32 位。尽管原始代码指定的是 8 位量，编译器却选择允许 最大 32 位的量。（例如，假设原始代码不是把 10 加到 5 上，而是计算 5 的 10 次方。5 和 10 两个量仍然放得进 8 位，但结果放不进去。）

  7. 将数据寄存器（edx）的内容加到累加器寄存器（eax）的内容上。 赋值尚未完成，但这就是加法 a + b。结果存放在累加器中，但还没有 存储到内存里。

  8. 只把累加器（al）的低 8 位移动到 rbp - 2，也就是第 3 步中存放 a 的位置。现在赋值已经完成（a = ...）。结合上一步， a = a + b; 现在已经完成。

  9. nop 看起来没有必要，但编译器生成它大概是为了让 pop 语句落在 偶数编号的内存地址上。取决于硬件的架构和操作系统的特性，仔细的代码 字节对齐往往更高效，有时则是绝对必要的。

  10. pop 通过将 rbp 重置回初始状态来清理内存。随后 rbp 就可以 被下一个程序使用。

  11. ret。当你在 Bash 提示符下键入程序名来启动程序时，实际上就像调用 子程序一样在调用该程序。在代码的这个位置，return 将把控制权交还给 Bash（它是一个持续运行的程序，听候你的吩咐，并把它无法处理的任务分派给 其他程序）。

在 official Intel reference documents 中可以找到更详尽的介绍。不过， 十卷的篇幅有点让人吃不消。

产生汇编语言/机器语言清单还有其他方法，但上面是我能找到的最不啰嗦的方法。

Linux 上最流行的两个汇编器是 GNU Assembler`_（``gas`，又称 as）和 Netwide Assembler`_（``nasm`）。两者使用许多相同的助记符，产生相同的 机器码，但在语法上略有差异（例如，gas 用 # 作注释分隔符，而 nasm 用 ; 作注释分隔符）。

gas 已紧密融入 Linux 的体系结构，它是 GNU Compiler Collection （gcc，旧称 GNU C 编译器）的一部分，除 gas 外还包括 C、 FORTRAN、C++、Go 和 Java 等。

在类 Debian 系统上，gas 是 binutils 包的一部分。如果你还没有安装 gcc 包，我也建议安装它。nasm 则是独立的包。
